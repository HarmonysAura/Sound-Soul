## Reality classification system

Every scientific, technical, cosmic, or future-facing component should carry an appropriate classification:

| Class | Meaning |
| --- | --- |
| Class A — Established | Supported by strong scientific evidence and/or existing engineering capability. |
| Class B — Active Research | Scientifically credible but technologically immature. |
| Class C — Theoretical | Supported by mathematical or physical frameworks but requiring major breakthroughs. |
| Class D — Speculative | Conceptual possibilities without sufficient evidence for current engineering claims. |
| Fiction / Lore | Creative universe material that is intentionally fictional. |

No fictional or speculative element should be represented as established real-world fact.

## Core operating models

### Aura Master Data Fabric™

Core components include Knowledge Graph, Entity Resolution, Canon Engine, Memory, RAG, Provenance, Metadata, Data Governance, Version Control, Semantic Indexing, Event History, Source Verification, Confidence Scoring, and Contradiction Detection.

Important entities should maintain `ENTITY_ID`, `NAME`, `TYPE`, `STATUS`, `SOURCE`, `PROVENANCE`, `OWNER`, `RELATIONSHIPS`, `VERSION`, `CREATED_AT`, `UPDATED_AT`, `CONFIDENCE`, `REALITY_CLASS`, and `CANON_STATUS`.

### Canon Engine

Canon states are Verified, Approved, Provisional, Research, Speculative, Fiction, Deprecated, and Archived. Canon changes must preserve history; historical canon should never be silently overwritten.

### Agent Operating System

Every AI agent should have a defined identity, role, mission, owner, model, tools, permissions, resource limits, data access, authority scope, risk class, escalation path, audit log, version, and status.

Agent lifecycle: Create → Configure → Evaluate → Authorize → Deploy → Monitor → Audit → Update → Retire.

Agents must operate within explicit authority boundaries. No implicit unlimited authority.

### Human oversight

- Low risk → Automation
- Medium risk → Human review
- High risk → Specialized oversight
- Critical risk → Strong authorization + multi-party control

## Design philosophy

Calm but urgent. Brilliant but practical. Aggressive in building. Cautious in release. Obsessed with truth. Comfortable with long-horizon bets.

Core questions:

- What can we build?
- Should we build it?
- How do we build it safely?
- Who benefits?
- Who has authority?
- Who can audit it?
- What happens if it fails?
- What happens if it succeeds?
- What happens 100 years from now?

## Final principle

Build boldly. Verify constantly. Protect human agency. Govern power. Preserve knowledge. Create culture. Expand responsibly. Learn from failure. Design for future generations. Reach for the stars without losing our humanity.
